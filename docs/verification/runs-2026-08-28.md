## Three defects

### The node does not exit on the DTLS demux path

Drain completes correctly — `all allocations drained` two seconds after SIGTERM —
and **two threads remain**. The process survives, SIGTERM does not take it, and a
watchdog had to kill it after 45 seconds.

An orchestrator would wait out its termination grace period on every restart and
then kill hard. That is what blocks flipping `demux` to default, and it is a
defect rather than missing evidence: both §7 P0 requirements the demux path exists
to provide are confirmed working.

Confirmed on this path: certificate hot-reload (0 → 1, no failures, media
uninterrupted) and the per-IP handshake rate limit (15 handshakes refused before
any DTLS state was created). Neither is available on the stock path, and neither
can be — `listen()` owns the socket and the handshake completes below `accept()`.

### The shared secret cannot be rotated without a restart

`rotation-under-load.sh` sent SIGHUP. The node does not handle SIGHUP — zero
references in `main.rs` — so it died, and the next check, "the old secret no longer
grants allocations", passed against a dead node. It would pass against any dead
node.

There is no other route: `UpdateConfig` carries `max_allocations`,
`max_allocations_per_user` and `max_bytes_per_sec_per_allocation`. Not the secret.

So §7's "credential rotation without downtime" holds for certificates and not for
the shared secret — which is the credential a leak would force you to change.
Ephemeral credentials expire on their own, which softens it; the secret they are
derived from still needs a restart.

### `handshake_failures` did not move on malformed input

Sending garbage at the DTLS port produced no change in the counter. Correct
behaviour is possible — the datagram may be discarded before the DTLS state
machine engages — but it means the check did not exercise the counter, and the
counter is documented as honest only on this path.

Recorded as a skip rather than a pass or a failure. A real failed handshake — wrong
cipher suite, expired certificate — would settle it.

## The caveat on mixed load

Four checks passed and the loss delta was 0.0000 pp both ways. That is true and
incomplete.

The TLS driver sent **17 % fewer frames** in the mixed phase than solo — 72 012
against 60 010 — while UDP sent the same, 180 060 against 180 059. Loss was zero
throughout, so a loss-delta check could not see it.

The node delivered everything it was given. What degraded was the TLS *generator*,
competing with the UDP generator for the sixteen cores they share. So the phases
were not equal, and a delta between unequal phases understates what a deployment
would see.

Worth stating because four green lines otherwise read as "measured under equal
conditions". Generators on other hosts would settle it.

## Three of my own conclusions that the runs overturned

**"The capacity measurement is uncertain by a factor of two."** It is not. I read
`sent ≈ recv` as a round trip; the receive task listens on the peer socket, so it
is one traversal. The forecast had been doubling — 26 nodes where 13 are needed.

**"The audit log is memory-only, so lifecycle events belong in syslog."** `open()`
and `open_with_rotation()` exist. The chain is replayed and verified on startup and
fails closed on a break. Start and stop events belong in it, and now go there.

**"The demux path fails to release its socket, and segfaults."** Neither. `kill -0`
succeeds on a zombie, so a check watched an already-dead process for 45 seconds;
and the only core on the host was bash's, from an interrupted run. The real defect
— two threads surviving — was found only after fixing the check that was reporting
a different one.

Each of the three took a measurement of a minute or two to settle, and each had
cost more than that in work built on top of it.

## Not run

**24-hour soak with `demux = true`.** The stock path holds the default on the
strength of a recorded 24-hour run, and correctness is a different claim from
stability. Blocked in practice by the exit defect above: a soak that ends with a
node that will not stop measures the wrong thing.

**Upgrade and rollback.** Not applicable — there is one version and no rollback
path in use.

**Cluster behaviour, hardware profiles.** Need more than one machine.
