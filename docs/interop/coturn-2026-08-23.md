# Interop against coturn's client — 2026-08-23

Five paths, all passing, against `turnutils_uclient` from coturn — a TURN client
written by other people, in another language, from an independent reading of
RFC 5766/8656 and RFC 7350.

| Check | Transport | Result |
|---|---|---|
| UDP | plain UDP | pass — 40/40 relayed |
| TURNS | TLS over TCP | pass — 40/40 relayed |
| **DTLS** | DTLS over UDP | **pass — 40/40 relayed** |
| IPv6 relay | UDP, `-g` | pass — 40/40 relayed |
| RFC 6062 | TCP relay over TURNS | pass — 40/40 relayed |

Reproduce with `scripts/verify/coturn-interop.sh`. Two minutes; coturn's client and
echo peer come from the distribution package.

## Why this record exists separately from the others

Every other functional check here was driven by `turna-load-test`, which is ours. It
proves the server does what *we* think the RFC says, and it says so in each record:
sharing a reading of the spec with the server — and, for the stream transports, a
library — means a mistake made in both places is invisible to it.

`turnutils_uclient` shares neither. Where it and turna agree about the wire, two
independent readings agree, which is the thing the in-tree client cannot establish for
the transport it drives.

**For DTLS this was the missing condition.** Correctness and endurance were already on
record (`docs/interop/transports-2026-08-19.md`,
`docs/soak/transport-load-2026-08-23.md`); what was absent was anyone else's
implementation, and no common client was known to speak TURN-over-DTLS. coturn does.

For UDP, TURNS, IPv6 and RFC 6062 this replaces self-testing with interop on paths that
previously had only our own evidence — RFC 6062 in particular, whose pipelined-bytes
case had been exercised only by the client written to exercise it.

## What it does not cover

**QUIC.** coturn does not implement TURN over raw QUIC, because no RFC defines it and
there is nothing to implement. That is not a gap in coturn; it is why QUIC cannot have
interop evidence from anyone at present.

**WebTransport.** Not a coturn transport either. Its independent check is a browser
(`webtransport-browser-2026-08-20.md`).

**Endurance.** These are short functional runs — 40 messages across 2 clients. Duration
lives in `docs/soak/`.

## Three faults, all in the harness

Worth writing down, because each looked like an interop failure and none was.

**An RSA key stops the DTLS listener from starting at all.** `webrtc-dtls` accepts EC
keys only and refuses with `dtls: listen: invalid private key type`. The first version
of this script generated RSA — deliberately, with a comment reasoning that coturn's
OpenSSL would prefer it — so the listener never came up and the client's handshake
failure read as a protocol disagreement. The comment was confident and wrong.

**turna has no plaintext-TCP TURN listener.** The only TCP ingress is TURNS, and the
RFC 6062 relay's connection state is adopted by the TLS bridge. Pointing coturn's `-t`
and `-T` at the UDP port earns `Connection refused` — the server being right and the
test being wrong. Both rows now use the TURNS port with `-S`.

**Backticks inside an unquoted heredoc run as commands.** A comment containing
`` `shared_secret` `` deleted the line it was documenting; the shell printed
`shared_secret: command not found` and the config went out without it. Third occurrence
of this in one week, now noted in the heredoc itself.
